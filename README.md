# GitTotte

**履歴から、安心して試す。**

GitHubに「取っ手」を付ける、Windows用の無料デスクトップアプリです。GitHubのファイルをPCへコピーしたり、PCで編集した内容を記録・送信したりできます。Gitのコマンドを覚えなくても、やりたいことから進める操作ガイドを用意しています。

旧名は **GitHug** です。v1.1.0からGitTotteに改名しました。

## こんな方におすすめ

- GitHubを使いたいけれど、コマンドや専門用語を覚えることが負担な方。
- 最新や過去の版を別フォルダーへ取り出して、今の作業と見比べたり試したりしたい方。
- 編集内容をPCに記録し、GitHubへ送る前に対象ファイルと送信先を確認したい方。
- やりたいことを選び、操作ガイドを見ながら進めたい方。

## ダウンロード・起動

**[Windows版 v1.1.2 をダウンロード](https://github.com/ISUKA-SSP/GitTotte/releases/download/v1.1.2/GitTotte-1.1.2-Windows-x64.zip)**

[配布ページ・更新内容](https://github.com/ISUKA-SSP/GitTotte/releases/latest) ／ [SHA-256チェックサム](https://github.com/ISUKA-SSP/GitTotte/releases/download/v1.1.2/GitTotte-1.1.2-Windows-x64.sha256)

Windows 11・64bit向け。Pythonのインストールは不要です。公開プロジェクトの取得に使うGitも同梱しています。

1. ZIPを **すべて展開** します。
2. 展開した `GitTotte` フォルダー内の **GitTotte.exe** を開きます。
3. 「＋ プロジェクト」でGitHubのURLを追加し、ファイルの保存先を選びます。
4. **「操作ガイド」** を押して、やりたいことを選びます。

`GitTotte.exe` だけを取り出さず、`_internal`・`tools` などを含むフォルダー全体で使ってください。インストーラーはありません。

## はじめて使う方へ

**まず「操作ガイド」を押してください。** やりたいことを選ぶと、実際の画面で操作しながら進められます。

![操作ガイドの入口。赤枠の「操作ガイド」を押してください（試用版1.1.0a15での画面）](docs/images/operation-guide-entry.png)

- 今やることを1つずつ案内し、操作する場所を水色の枠で示します。
- すでに選択できている手順は省略します。ドラッグが苦手な場合はボタンでも進めます。
- コピーや送信などが成功すると案内が完了します。確認画面のキャンセルや、途中でガイドを閉じることもできます。
- ガイドを閉じても、行った操作は取り消しません。進行中の処理も、閉じただけでは中断しません。
- APIキー・AIへの接続は不要です。

## できること

| やりたいこと | 操作 |
|---|---|
| 最新や過去のファイルを取り出す | 上の履歴を下のPC欄の空白へドラッグ。毎回新しいフォルダーへコピー |
| 同じフォルダーを別の版に更新 | 履歴を対象フォルダーの行へドラッグし、変更内容とバックアップ方法を確認 |
| 編集内容をPCだけに残す | PCのフォルダーを右クリック →「PCに記録だけ残す」 |
| PCの編集内容をGitHubへ送る | 下のフォルダーを上へドラッグし、ファイル・送信先・変更の説明を確認 |
| 履歴とPCのファイルを比べる | 上で履歴、下でフォルダーを選び、「比べる・取り込む → 作業フォルダーと比較」 |
| 作業ルート同士の違いを調べる・取り込む | 「比べる・取り込む」から取り込み元と先を選択。提案の作成・合流の確定はGitHubで操作 |
| 記録やバックアップを取り出す | 「保管した内容」から選び、「新しいフォルダーへ復元」 |
| ファイルを探す・普段のアプリで編集する | 左下のフォルダーツリー、エクスプローラーやVS Codeで開く操作 |
| コマンドを実行する | PCのフォルダーを選び「PowerShell／コマンド」。画面下のパネルで複数行の実行・途中の入力に対応 |
| よく使う版に目印を残す | 履歴やフォルダーの右クリックで「自分用メモ」。メモも検索対象 |
| 変更の説明を読む | 任意の「説明パネル」から、送信内容を確認してGeminiへ依頼 |

履歴の分岐・合流をグラフで追えます。履歴は作業ルートとタグからたどれる全件を表示し、検索・並べ替え・ページ切替に対応します。PR専用の履歴は通常の一覧に含めません。PCのフォルダーはCtrl・Shiftで複数選択でき、まとめてごみ箱へ移動したり、見つからない項目だけ一覧から取り除いたりできます。

履歴とPCの比較では、Gitの改行設定と `.gitattributes` に従って内容を判定します。Git管理のあるフォルダーは、そのフォルダーの改行・入力フィルター設定も使います。`.gitattributes` が手元にない場合は選択した履歴のものを参照します。比較は一時的な管理情報を使い、手元のファイルやステージ済みの内容を保持します。

「表示用語：**操作名／Git用語**」は画面を見ながら切り替えられます。Git用語で人に説明したいときにも使えます。

## ファイルをどう扱うか

- **履歴の取得だけでは作業フォルダーを更新しません。** 別フォルダーへのコピー・復元は毎回新しい場所を作ります。
- 同じ場所への更新は、確認して選んだ場合だけ行います。更新前の全体をZIPに保管できます。
- 更新時の「手元だけのファイルを残す」は、もとの履歴が分かる場合は初期状態でONです。もとの履歴にあるファイルへの編集は、選んだ版へ置き換わります。
- 作成元が分からないフォルダーや、上書き更新を許可していないフォルダーは、そのまま上書きしません。
- GitHubへの送信は別の作業用コピーで準備します。送信元のファイルやGit管理情報を直接書き換えません。
- GitHub側にも更新がある場合は、ファイルごとに **PCの内容／GitHubの内容／保留** を選んで確認できます。行単位の自動統合や、コードの編集機能はありません。
- PCの記録は元のフォルダーを編集・削除しても残ります。復元先で続きを記録することもできます。
- バックアップの復元はZIPにある設定や手元だけのファイルも対象です。PCの記録の復元は、その記録に保存した内容が対象です。どちらも元のメモを引き継ぎ、上書き更新はOFFから始まります。

大切なデータには別のバックアップも用意してください。[詳しい操作と制限](docs/操作ガイド.md)も確認できます。

## GitHubへの送信・非公開プロジェクト

PC側でGitHubへの認証と、対象プロジェクトへの権限が必要です。Git for Windowsがインストールされている場合はそちらを優先し、普段の認証設定を使います。同梱Gitだけでは認証の準備が済んでいるとは限りません。

**ChatGPTのGitHub接続は、このアプリには引き継がれません。** 認証を準備していない場合は、まず公開プロジェクトの閲覧・コピーから試せます。

## AIによる説明（任意）

Geminiを使わなくても、操作ガイドを含む基本機能は利用できます。

1. 「説明パネル」を開き、⚙からモデル名とAPIキーを設定します。
2. 履歴・ファイルを選び、「送信内容を確認」で対象を確認します。
3. 「Geminiへ送って説明する」を押します。

選択しただけでは送信しません。本文・差分を含めるかも選べます。APIキーは初期状態では保存せず、希望した場合だけWindowsの資格情報マネージャーへ保存できます。設定ファイルにはキーを書きません。

Google側の利用条件・料金・上限が適用されます。説明には誤りが含まれる場合があります。設定・DB・鍵などはファイル名で除外しますが、コード中の秘密情報を完全に検出する機能ではありません。送信前の表示を確認してください。

## PowerShellを使うとき

パネル右端の「✖」は画面を隠す操作です。コマンドはそのまま動きます。「終了」はPowerShellと、そこから起動した処理を終了します。PowerShellで `exit` を実行した場合も、パネルに **「終了しました」** と表示されてから、プロジェクトの保存先変更やアプリの終了へ進んでください。作業場所とコマンドの内容は実行前に確認してください。

コマンド欄はEnterで改行し、Ctrl＋Enterで実行します。「途中の入力」もCtrl＋Enterで送信します。新しいコマンドの実行時は最新の出力へ戻り、途中で過去の出力をスクロール・選択すると表示の追従を止めます。「最新の出力へ」で再開できます。実行中は動く表示と経過秒数、処理が終わると「コマンド受付待ち」を表示します。処理途中の質問待ちは自動判定しないため、出力を確認して回答してください。

「コマンド履歴」から実行済みのコマンドを入力欄に戻し、内容を確認して再実行できます。履歴は重複をまとめて直近50件、アプリを閉じるまで保持します。「途中の入力」は履歴に含めません。

PowerShellが停止してパネルも閉じているときは、F5で選択中プロジェクトのGitHub履歴を更新できます。PowerShellの動作中（パネルを隠した場合も含む）や、ほかの操作中は更新しません。

初期配布のv1.1.0では、PowerShellを終了したあとにプロジェクトや履歴を選ぶと、Gitが起動できず `WinError 6` が出る場合がありました。v1.1.1にはこの修正が入っています。

## GitHugからの更新・保存先

アプリを終了し、新しいZIPを別の場所へすべて展開して `GitTotte.exe` を起動してください。旧アプリのフォルダーに上書きする必要はありません。

既存の設定・登録フォルダー・自分用メモ・保存済みAPIキーは引き継ぎます。互換性のため、設定の保存先は引き続き `%APPDATA%\GitHug\settings.json` です。内部のPythonパッケージ名にも `githug` が残っています。

コピーしたファイル・PCの記録・バックアップなどは、アプリで指定した保存先にあります。アプリ本体を削除しても、それらのデータや設定は自動削除しません。

保存先を整理したい場合は、`history.git` を含むプロジェクトフォルダーを丸ごと新しい場所へコピーします。GitTotteで対象プロジェクトを選び「コピー・履歴の保存先」でコピー先を指定してください。先に手動で移動していた場合も、移動先を指定できます。フォルダーの記録と自分用メモの紐づけが更新されます。共通の保存先と、他のプロジェクトの設定は引き続き使えます。

## LivingAgent

画面の二人は、デスクトップマスコット **LivingAgent** のステラとシリカです。処理中に考えたり、コピー中に箱を運んだりします。動きは設定からOFFにできます。

[LivingAgentの紹介・配布ページ](https://github.com/ISUKA-SSP/living_agent_public/) ／ [LivingAgentのダウンロード](https://github.com/ISUKA-SSP/living_agent_public/releases)

## 制限・配布について

- submoduleやGit LFSの実体取得、Pythonなどの実行環境の自動準備には対応していません。
- コードを編集するIDEではありません。編集は普段のアプリを使います。
- Windows版にコード署名はありません。ChromeやWindowsの警告・判定は環境によって異なります。
- 配布前にWindows上のテスト、EXE起動、同梱Git・PowerShell・主要画面の確認、DefenderによるフォルダーとZIPの検査を行います。検査の通過はすべての環境での動作や安全性を保証するものではありません。

アプリの「使い方・環境 → 不具合・要望を送る」から、バージョンとOS情報を入力済みの報告ページを開けます。内容を確認してから送信してください。GitHubアカウントが必要です。

不具合や要望は[Issues](https://github.com/ISUKA-SSP/GitTotte/issues)へ。再現手順・バージョン・エラー文を添えてください。APIキーや個人情報は載せないでください。

## ソースから起動・開発

Python 3.11以降（tkinterを含む）とGitが必要です。Windows版のビルド・動作確認はPython 3.13で行っています。

```powershell
python -m pip install -r requirements.txt
python -m gittotte
```

```powershell
python -m unittest discover -s tests -v
```
